# 投稿の作り方（コンテンツ戦略）

## ねらう人
- 共働き・子育て中で、家事の時間を減らしたい
- 家が狭くて片付かない、でも何を買えばいいか調べる時間がない
- ふだんの買い物は Amazon（プライム会員・セールでまとめ買い）

## 収益の導線
```
インスタ投稿（保存される図解）
  → キャプションで「プロフィールのリンク」へ誘導
  → リンク集ページ（GitHub Pages）の、投稿と同じ見出し
  → 商品ごとの「Amazonで見る」 → Amazonで購入 → 紹介料
```
キャプション内のURLはクリックできないので、**導線の本命はプロフィールのリンク**。
キャプションにもリンク集ページのURL（`content/account.json` の `siteUrl`）を `buildCaption()` が自動で入れる（コピーして開きたい人向け）。
だから「リンク集ページに投稿と同じ名前の見出しがある」ことが大事。投稿するとページが自動で更新される。
価格・在庫は Amazon の商品ページで最新が出るので、こっちでは書かない。

アソシエイトの審査に通ったら、ストアフロントも作ってリンク集ページにボタンを足す（[setup-guide.md](setup-guide.md) の最後）。

## 投稿の型（カルーセル7枚）
| 枚目 | 中身 |
|---|---|
| 1 | 表紙: 「保存版」ラベル＋悩みが伝わるタイトル＋サブタイトル＋イラスト |
| 2〜6 | 1アイテム1枚: 番号・呼び名・イラスト・**選ぶときのチェックポイント3つ**・「選んだ商品はプロフのリンクから」 |
| 7 | まとめ: 「プロフィールのリンクの『○○』から見られるよ」＋保存のお願い |

- 文字はすべてプログラムで描く（誤字・文字化けなし）。AI が作るのはイラストだけ（1投稿6枚）
- 全スライドの左下に「PR｜AIにより作成」、右下にアカウント名が自動で入る

### チェックポイントの考え方
- スライドに書くのは「この種類のアイテムを選ぶならここを見て」という条件。特定商品の性能や使用感は書かない
- リンク集ページに載せる商品は、**その3つを全部満たすもの**をユーザーが Amazon で選ぶ → スライドと実物が食い違わない
- 例（室内物干し）: 「使わない日は薄くたためる」「幅を伸縮して調整できる」「キャスター付きで動かせる」

### テーマの選び方
- 「○○がラクになる」「○○をゼロにする」など **悩み→解決** の形
- 季節先取り（10月: 衣替え・部屋干し / 11月: 冬支度・結露・大掃除 / 12月: 年末）
- Amazonの大型セール（プライム感謝祭・ブラックフライデー・初売りなど）の **1週間前** に「セール前にチェック」系を置く。セールの日程は毎年変わるので公式発表で確認

## キャプションのテンプレ

post.json の `caption` には **本文だけ** を書く。1行目の `#PR｜画像・文章はAIにより作成`、リンク集ページのURL、末尾のアソシエイト開示文、ハッシュタグは `buildCaption()` が自動で付ける。

```
（1行目: 悩みに刺さる一言。例「部屋干しの生乾き臭、もう諦めてない？」）

部屋干しをラクにするアイテムを、選ぶときのチェックポイントつきで5つまとめたよ。

01 ○○ … 一言
02 ○○ … 一言
03 ○○ … 一言
04 ○○ … 一言
05 ○○ … 一言

📌 買う前に見比べられるように保存しておいてね
▶ 紹介したアイテムはプロフィールのリンクの「見出し名」から見られるよ
価格・在庫はリンク先の Amazon で最新をチェックしてね
```

実際に投稿されるキャプションはこうなる:
```
#PR｜画像・文章はAIにより作成

（本文）

🔗 リンク集 https://www.monodelife.com/

Amazonのアソシエイトとして、mono.delifeは適格販売により収入を得ています。

#amazonで買えるもの #暮らしのアイデア #部屋干し #洗濯グッズ #家事ラク
```

## ルール（必ず守る）
`status --approve` と `publish` は `lib/compliance.js` で自動チェックして、引っかかったら止まる。

| ルール | 理由 |
|---|---|
| 価格・送料・「○円台」を書かない | Amazonの価格はすぐ変わり、古い価格の掲載は規約違反。価格は商品ページで見てもらう |
| ★・評価の数字・レビュー件数・順位・「高評価」「ベストセラー」を書かない | Amazonのレビュー・星評価は Creators API 経由以外の表示が禁止 |
| 「最安」「No.1」「必ず」「絶対」などの断定・誇大表現を使わない | 景品表示法・規約 |
| 「使ってみた」「愛用」「購入品」など体験談にあたる表現を使わない | 使っていない商品の体験談はステマ・不実表示になる |
| 「Amazon公式」「Amazonおすすめ」など公式と誤解される表現を使わない | 運営規約（Amazonが支援・推奨しているような表示の禁止） |
| 「プライム対象」「翌日届く」など配送条件を書かない | 商品ごと・時期ごとに変わる |
| Amazonの商品画像・スクショを使わない。画像はイラスト・図解だけ | 商品画像のダウンロード・キャプチャ使用は禁止 |
| 投稿を「宣伝する（ブースト）」しない | 有料・ブースト広告経由の購入は紹介料の対象外（2026/4/20 改定） |
| #PR・AI表記・開示文を消さない | ステマ規制（2023/10〜）、Amazonの AI 利用表記（2026/4/20〜）、運営規約 第5条 |
| ハッシュタグは5個まで | 多すぎると逆効果 |

## ハッシュタグ
毎回 固定2個＋テーマ別3個 の5個にする。

- 固定: `#amazonで買えるもの` `#暮らしのアイデア`
- 収納系: `#収納アイデア` `#すっきり暮らす` `#片付け`
- 家事系: `#家事ラク` `#時短家事` `#暮らしを整える`
- キッチン: `#キッチン収納` `#キッチングッズ`
- 洗濯: `#部屋干し` `#洗濯グッズ`
- 掃除: `#掃除グッズ` `#大掃除`
- 季節: `#冬支度` `#衣替え` `#結露対策`

## 投稿スケジュール
- 最初の2週間: **毎日8時に1本**（GitHub Actions で自動）
- 新しいアカウントで一気に大量投稿すると制限がかかりやすいので、1日1本を守る
- ストーリーズ（リンクスタンプで直接飛ばせる）は API で貼れないので、余裕があればスマホから手動で。リンク先はリンク集ページの見出し（`<ページのURL>#<投稿id>`、例 `…/#01_heyaboshi`）

## 週1回の振り返り（毎週日曜）
1. Instagram のインサイト: 保存数・プロフィールへのアクセス・リンクのタップ数
2. アソシエイト・セントラルのレポート: クリック数・注文数
3. 保存が多かったテーマの「続編」を次週に入れる（例: キッチン収納がウケたら「冷蔵庫」「シンク下」へ）
4. Claude に「今週のインサイトはこう。次の14本を作って」と頼む（themes.json にテーマを足して build-posts から）

## 売上が増えてきたら
- **審査に通ったら（申請から180日以内に3件）**: ストアフロントを作る（[setup-guide.md](setup-guide.md) の「9. 審査に通ったら」）
- **直近30日で10件を超えたら**: Creators API が使える。Claude に「Creators API を入れて」と頼めば、商品候補の自動提案を足せる。画像は24時間ごとに更新できないので、API を入れても価格・★はスライドに載せない
